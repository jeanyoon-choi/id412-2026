## 7. 수업에서 실습하는 방식 [#7-how-we-work-in-class]

- 코드를 따로 주지 않는다. Claude Code를 같이 켜고, 빈 폴더에서 실험 하나하나를 현장에서 새로 만든다. 너도 네 노트북에서 동시에 똑같이 한다
- 이유: 핵심은 코드가 아니라 루프다. 설명한다 → 에이전트가 만든다 → 본다 → 뭐가 틀렸는지 말한다 → 반복. 루프는 완성된 파일을 읽어서가 아니라 직접 돌려봐야 배운다
- 실험 하나 = 폴더 하나: `app/experiments/w1/<kebab-name>/`. 하는 일을 따서 이름 짓는다 (`time-interval`, `mouse-trail`). `test1`은 안 된다
  - 안에 `page.tsx` (+ `page.module.css`). 헬퍼는 옆에. 에셋은 `public/experiments/w1/<kebab-name>/`
  - 에이전트가 폴더에 짧은 `README.md`를 쓴다: 뭔지, 입력, 파라미터, 실행법. 규칙은 `docs/experiments/README.md`에 있고 에이전트는 `AGENTS.md`로 그걸 안다
- 모든 실험을 시작하는 프롬프트는 대충 이렇다: "`app/experiments/w1/<name>`에 화면 꽉 채운 캔버스를 만들고 ...". 그다음 localhost:3000/experiments/w1/name을 보면서 대화한다
- 변형은 새 폴더다 (`mouse-trail-2`). 고치지 않는다. 끝난 실험은 기록으로 남긴다
- 실험이 돌아갈 때마다: `git add .` → `git commit -m "w1: <name>"`. 위험한 변경 전에: 커밋. 에이전트가 망가뜨리면: `git restore .`
- 뒤처지면 코드를 따라잡지 마라. 루프를 따라잡아라. 본 것을 네 말로 에이전트에게 만들게 해라

## 8. 코딩 시작 [#8-lets-start-coding]

**Bottom-up 팅커링**

- 나중에 기말이나 큰 프로젝트를 할 때는 top-down이 필요하다. 컨셉 먼저, 시스템, 그다음 부품. 거기까지 간다
- 하지만 지금은 처음이고 받아들일 게 많다. 그래서 이번 주는 bottom-up이다. 작고 귀여운 실험, 하나에 아이디어 하나, 하나에 10분
- 목표는 감을 잡는 것. 캔버스가 뭘 할 수 있는지, 시간이 뭘 하는지, 마우스가 뭘 하는지, 이미지 그리드가 뭘 하는지

- 크리에이티브 코딩은 원래 이렇게 돌아간다: 만지작거리고, 알아채고, 아름다운 걸 남긴다

## 9. GLSL [#9-glsl]

- <Term id="glsl" />이란?
  - OpenGL Shading Language: GPU에서 도는 작은 C 계열 언어. Javascript가 아니다
  - 프로그램이 정점마다 한 번(버텍스 셰이더), 픽셀마다 한 번(프래그먼트 셰이더), 전부 병렬로 실행된다
  - 프래그먼트 셰이더: 픽셀 좌표(그리고 시간, 마우스, …)를 받아 색을 돌려준다. 그게 전부다
  - 수천 개 픽셀을 한 번에 → Canvas 루프에서 너무 느린 것들이 공짜가 된다
- Three.js와는 어떻게 연결되나?
  - `ShaderMaterial`: 버텍스/프래그먼트 셰이더를 직접 쓰는 머티리얼
  - `uniforms`: 매 프레임 Javascript에서 셰이더로 넘기는 값 (시간, 마우스, 해상도, …)
  - 화면 꽉 채운 평면 하나 + 프래그먼트 셰이더 = GPU가 그리는 2D 캔버스
- 무엇에 좋은가?
  - 픽셀 단위 필드: 그라데이션, 노이즈, 흐름, 거리 필드, 블러, 피드백
  - 대량의 파티클 / 인스턴스
  - 후처리: 프레임 전체에 거는 효과
- 안 맞는 것: 레이아웃, 텍스트, UI 로직. 그건 React/CSS에 맡겨라
- 레퍼런스
  - The Book of Shaders [LINK](https://thebookofshaders.com/)
  - Shadertoy [LINK](https://www.shadertoy.com/)
  - Three.js ShaderMaterial [LINK](https://threejs.org/docs/#api/en/materials/ShaderMaterial)

## 10. Three.js [#10-threejs]

- <Term id="threejs" />란?
  - Javascript 3D 라이브러리
  - 3D + Javascript, 웹 3D, 오픈소스(무료!), 코딩 기반
  - 인터랙티브, 접근 쉬움, 기성 3D 모델과 결합 가능
  - Vanilla Three.js = Vanilla Javascript + Three.js
    - 즉 React Three를 안 쓰는 것
    - 가능하지만 코드가 길어지고 React 로직과 안 묶인다
- React-Three란?
  - Three.js를 React 방식으로 효율적으로 쓰기 위한 프레임워크/통합 전략 묶음
  - **<Term id="r3f">React-Three Fiber</Term>:** Three.js용 React 렌더러 [LINK](https://r3f.docs.pmnd.rs/getting-started/introduction)
    - https://codesandbox.io/p/sandbox/5g22g7
  - **React-Three Drei:** 바로 쓰는 유틸/헬퍼 모음 [LINK](https://github.com/pmndrs/drei)
  - React-Three Postprocessing: 후처리 효과 [LINK](https://github.com/pmndrs/react-postprocessing)
  - React-Three Rapier/Cannon: 물리 라이브러리 [LINK](https://github.com/pmndrs/react-three-rapier)
  - React-Three 통합은 아니지만, React Spring (애니메이션 라이브러리) [LINK](https://www.react-spring.dev/)
- 왜 Three.js인가?
  - Cinema 4D: 정적인 3D 영상, GUI 기반, 접근성 높음, 인터랙티브 낮음
  - Unity: 인터랙티브 3D 게임, GUI + C# 코딩, 접근성 낮음, 인터랙티브 높음
  - Three.js: 인터랙티브 웹 3D 환경, Javascript 코딩, 접근성 중간, 인터랙티브 중간
  - Three.js를 쓸 때
    - 인터랙티브 웹
    - 통합된 웹
    - 접근 쉬운 데모 (설치 없음)
    - '와우' 효과
    - 웹의 미래 / WebXR
- 왜 3D 웹 개발을 배우나?
  - 단순히 더 나은 비주얼과 미감
  - 웹의 미래일 수 있다
    - 웹 UI의 미래
    - 몰입형 웹의 미래
    - 네가 판을 이끌 수 있다!
  - 가파른 학습 곡선… 작게, 가볍게 시작

## 11. 배포 [#11-deployment]

1. 배포: localhost에서 짠 웹앱을 전 세계에서 접속 가능하게 만드는 것!
2. Next.js → <Term id="vercel" />로 쉬운 배포
3. Vercel 가입 https://vercel.com/
4. 먼저 코드를 GitHub에 올려야 한다. VS Code 터미널에서
   1. `git add .`
   2. `git commit -m "Update"`
   3. `git push`
5. 이제 GitHub의 레포가 최신 상태다
6. Vercel로 https://vercel.com/
7. Add New > Project > Import Git Repository > 'Import' > **Framework Preset을 Next.js로 >** Deploy
8. 짠!
9. 이제부터 `git push`할 때마다 다시 배포된다
