## 1. API 소개 [#1-api-introduction]

- <Term id="api" />란?
  - 컴퓨터와 컴퓨터, 또는 프로그램과 프로그램 사이를 이어 주는 연결이다. 소프트웨어 인터페이스의 한 종류로, 다른 소프트웨어에 서비스를 제공한다. - Wikipedia
- API의 종류
  - 날씨, 뉴스, 지도, 공공데이터
  - OpenAI API, Anthropic API (Claude)
  - Replicate API
  - Microsoft Azure/AWS/Google Cloud
- Next.js와 연동하기
  - App Router: <Term id="routeHandler">Route Handler</Term> [LINK](https://nextjs.org/docs/app/building-your-application/routing/route-handlers)
    - Route Handler를 쓰면 백엔드 서버를 따로 만들지 않고 Next.js 안에 서버 쪽 로직을 바로 작성할 수 있다
    - `app/api/<name>/route.ts`에 작성 → 페이지에서 `fetch("/api/<name>")`로 호출
    - 서버에서 실행된다. API key는 브라우저로 절대 넘어가지 않는다
    - Route Handler는 Vercel에 함께 배포된다 (socket relay는 배포되지 않는다)

| [공공데이터포털](https://www.data.go.kr/) | 한국 공공데이터 | 무료 key |

**API key가 필요 없는 경우**: 페이지에서 `fetch`로 호출한다

```tsx
const response = await fetch(
  "https://api.open-meteo.com/v1/forecast?latitude=36.37&longitude=127.36&current=temperature_2m,wind_speed_10m",
);
const data = await response.json();
console.log(data.current.temperature_2m, data.current.wind_speed_10m);
```

**API key가 필요한 경우**: Route Handler에서 호출한다

- 1단계. 가입한 뒤 API key를 발급받는다
  - New York Times: https://developer.nytimes.com/
- 2단계. API key를 <Term id="env">`.env.local`</Term>에 저장한다: `NYT_API_KEY=...`
  - `.env.local`이란? 환경 변수를 담는 파일. 서버에서만 읽는다
  - 이름 앞에 `NEXT_PUBLIC_`을 붙이면 안 된다. 이 접두사가 붙은 변수는 모두 브라우저까지 전달된다. 곧 외부에 공개된다는 뜻이다
- 3단계. <Term id="gitignore">`.gitignore`</Term>를 확인한다. `.env*`는 이미 들어 있다. API key는 절대 커밋하면 안 된다
- 4단계. API를 호출하는 코드를 Route Handler에 작성한다: `app/api/<name>/route.ts`. API key는 `process.env.NYT_API_KEY`로 읽어 온다
- 5단계. 프론트엔드에서는 이 Route Handler를 fetch로 호출한다

## 3. 사운드: Tone.js [#3-sound-tonejs]

- <Term id="webAudio" />: 브라우저의 오디오 엔진. oscillator, 샘플, 이펙트, 분석(볼륨, FFT) 기능을 제공한다
- <Term id="tonejs" />: Web Audio를 기반으로 만든 Javascript 라이브러리. 음악가에게 친숙한 개념(Synth, Transport, Effect)으로 쓸 수 있다 [LINK](https://tonejs.github.io/)
- 템플릿에 이미 설치되어 있다: `tone`
- 규칙
  - 사용자가 탭하거나 클릭한 뒤에만 오디오를 시작할 수 있다. 이벤트 핸들러 안에서 `await Tone.start()`를 호출한다
  - 마이크 입력을 받으려면 HTTPS가 필요하다 ([W2 A2](/lecture-materials/w2#a2-https-for-local-dev-pnpm-devmobile) 참고)

```tsx
import * as Tone from "tone";

async function play() {
  await Tone.start();
  const synth = new Tone.Synth().toDestination();
  synth.triggerAttackRelease("C4", "8n");
}
```

**사운드를 만드는 방법**

1. 합성: `Tone.Synth`, `Tone.FatOscillator`, `Tone.NoiseSynth`. 파라미터 → 주파수, 볼륨
2. 샘플: `public/`에 넣어 둔 녹음 파일을 `Tone.Player` / `Tone.Sampler`로 재생한다
3. 시퀀싱: `Tone.Transport`, `Tone.Loop`. 템포를 파라미터로 쓴다
4. 이펙트: 소스와 스피커 사이에 `Tone.Filter`, `Tone.Reverb`, `Tone.Distortion`, `Tone.FeedbackDelay`를 연결한다
5. 마이크를 입력으로 쓰기: `Tone.UserMedia` + `Tone.Meter` / `Tone.FFT`
6. 음성: 브라우저의 `speechSynthesis`를 쓰거나, Route Handler를 거쳐 TTS API를 호출한다

**사운드 예제**

1. Tone Pad: 포인터 → 음높이, filter: [sound/tone-pad](/experiments/w3/sound/tone-pad)
2. 데이터 → 사운드 (드론, 바람, 심장 박동, 충격음): [w1/snp](/experiments/w1/snp) → `sound.ts`
3. 마이크 → 파라미터: [w1/video](/experiments/w1/video)

## 4. <Term id="unreal" /> [#4-unreal]

- 모바일로 웹 페이지뿐 아니라 Unreal Engine도 조작할 수 있다. 거치는 길은 W2와 같다. 모바일 → relay → 출력. 출력이 브라우저에서 Unreal로 바뀔 뿐이다
- 예제 레포: https://github.com/jeanyoon-choi/mobile-to-unreal-realtime-backbone
- 이 예제가 하는 일: 모바일에서 손가락을 드래그하면 Unreal 안의 구(sphere)가 따라 움직인다
  1. 모바일에서 XY 패드가 있는 웹 페이지를 연다
  2. 손가락을 드래그하는 동안 페이지가 손가락 위치(`x`, `y`)와 누르는 세기(`pressure`)를 WebSocket으로 relay에 보낸다. 1초에 25번 보낸다
  3. relay(Node.js)는 가장 최근 위치만 남겨서 Unreal로 넘긴다. 1초에 30번 넘긴다
  4. Unreal에서는 C++ 액터 하나가 이 값을 받아서 구를 움직인다
- 수업에서 쓰는 relay와 다른 점: 브라우저는 Socket.io 메시지를 받을 수 있지만 Unreal은 받지 못한다. 그래서 relay가 마지막 구간을 UDP로 보낸다. UDP는 네트워크로 데이터를 보내는 더 단순한 방식이고, Unreal이 받을 수 있다
- 실행하려면 Node.js 20 이상, pnpm 11, Unreal Engine 5.8이 필요하다
  1. `pnpm install`을 한 뒤 `pnpm dev`를 실행한다. 모바일용 페이지(3000 포트)와 relay(4000 포트)가 켜진다
  2. 같은 Wi-Fi에 연결한 모바일에서 `http://<YOUR_IP>:3000`을 연다
  3. Unreal Engine에서 `unreal/MobileToUnrealBackbone/MobileToUnrealBackbone.uproject`를 연다
  4. 모바일에서 드래그하면 Unreal의 구가 움직인다
- 폴더 구성: `apps/mobile/` (모바일 페이지), `relay/` (relay), `unreal/` (Unreal 프로젝트), `docs/` (동작 방식에 대한 자세한 설명)

## 부록. 프로젝션 매핑 [#appendix-projection-mapping]

- 1층 갤러리(Black Room)에는 프로젝터가 두 대 있고, 벽 하나에 한 대씩 쏜다
- 프로젝터가 쏘는 화면은 벽보다 크다. 그래서 화면의 일부만 벽에 맺힌다
  - 왼쪽 벽에는 화면 중 1920 × 602만큼, 오른쪽 벽에는 1675 × 602만큼 맺힌다

- 따라서 화면 전체를 채우도록 만든 페이지는 벽에 맞지 않고, 일부가 벽 밖으로 나간다. 콘텐츠가 벽에 딱 맞게 놓이도록 조정하는 일이 프로젝션 매핑이다
- 브라우저에서 하는 방법
  1. 페이지 전체를 검은색으로 만든다. 검은색 부분은 프로젝터가 빛을 쏘지 않아서 보이지 않는다
  2. 페이지 위에 상자를 하나 두고, 콘텐츠를 전부 그 상자 안에 넣는다
  3. 전시장에서 상자의 네 변이 벽의 가장자리와 만날 때까지 상자의 위치와 크기를 조절한다
- 예제: projection-mapping ([left](/experiments/w3/projection-mapping?side=left) · [right](/experiments/w3/projection-mapping?side=right)) → `app/experiments/w3/projection-mapping/`
  - 프로젝터 한 대에 노트북 한 대를 연결한다. 한쪽에서는 `?side=left`를, 다른 쪽에서는 `?side=right`를 연다
  - 슬라이더 네 개(top, left, width, height)로 상자를 움직인다. 벽에 맞으면 그 숫자 네 개를 `MappingFrame.tsx` 맨 위의 `FRAMES`에 적어 넣고 hide를 누른다
  - `Content.tsx`가 내 콘텐츠다. 크기는 창 전체(`100vw` / `100vh`)가 아니라 상자(`100%`)를 기준으로 잡는다
- 참고: https://github.com/jeanyoon-choi/xdlab-mapping
