## 5. Create a New Next.js App

Two steps today, in this order: first a bare app from scratch, then my template. So you know what a bare Next.js app is, and what the template adds on top. Otherwise the template is magic, and magic you can't debug.

**Step 1. Open VS Code and a terminal**

1. Open VS Code. File → Open Folder… → pick (or make) a folder where you keep projects, e.g. `Documents/code`. This folder is where every project of this workshop will live
2. Open the terminal inside VS Code: menu **Terminal → New Terminal**, or the shortcut `` Ctrl+` `` (the key left of `1`). A panel opens at the bottom. That is a command line, already pointed at the folder you opened
3. Whatever you type there and press Enter runs on your computer. Everything below happens in this panel

**Step 2. Create the app**

1. Type `pnpm create next-app@latest` and press Enter
   - `pnpm create` → "run a project generator"; `next-app@latest` → "the Next.js one, newest version". pnpm downloads it and runs it
2. It asks a few questions. Arrow keys to choose, Enter to confirm

```
✔ What is your project named? … scratch
✔ Would you like to use TypeScript? … Yes
✔ Would you like to use ESLint? … Yes
✔ Would you like to use Tailwind CSS? … No
✔ Would you like your code inside a `src/` directory? … No

```

   - Name: `scratch` (anything). TypeScript **Yes**. Tailwind **No** (we use CSS Modules). `src/` No. App Router **Yes**. Turbopack Yes. Alias No
3. It prints `Success! Created scratch at …`. A new folder `scratch/` appeared in the file panel on the left, with the packages already installed
4. Docs: [create-next-app](https://nextjs.org/docs/app/api-reference/cli/create-next-app)

**Step 3. Start it**

1. `cd scratch` → "change directory": the terminal now points inside the new folder. (Or: File → Open Folder → scratch, and open a new terminal)
2. `pnpm dev` → "run the script called dev from package.json". That script is `next dev`: it starts a development server, which builds your pages on the fly and reloads the browser whenever you save a file. You see:

```
▲ Next.js 16.4.0 (Turbopack)
- Local:         http://localhost:3000
- Network:       http://192.168.0.12:3000
✓ Ready in 241ms
```

   - `Local: http://localhost:3000` is the address. `localhost` = this computer, `3000` = the port the server listens on
   - The terminal is now busy running the server. Leave it. `Ctrl+C` stops it. To type other commands, open a second terminal with the `+` in the terminal panel
3. Open http://localhost:3000 in Chrome. You get the Next.js welcome page

**Hello World~! (scratch)**

1. Where is that page coming from? In the file panel open `scratch/app/page.tsx`. That file *is* localhost:3000
   - `app/page.tsx` → what you see at `/`
   - `app/layout.tsx` → the frame around every page (html, body, fonts). You rarely touch it
   - `app/globals.css` → styles for the whole site

```tsx
      <h1>Hello World~!</h1>
      <p>This is app/page.tsx. Change this text and save.</p>
    </main>
  );
}
```

   - A page is a function that returns HTML-looking code (JSX). `export default` means "this is the page"
   - The browser updates by itself. No refresh, no restart. That is the dev server doing its job

## 7. How We Work in Class

- I don't hand out code. We open Claude Code together and build each experiment live, from an empty folder. You do the same on your laptop, at the same time
- Why: the point is not the code. It is the loop. Describe → agent builds → look → say what's wrong → repeat. You learn the loop by doing it, not by reading a finished file
- One experiment = one folder: `app/experiments/w1/<kebab-name>/`. Name it after what it does (`time-interval`, `mouse-trail`), not `test1`
  - `page.tsx` (+ `page.module.css`) inside. Helpers next to it. Assets in `public/experiments/w1/<kebab-name>/`
  - The agent writes a short `README.md` in the folder: what it is, inputs, parameters, how to run. The rules are in `docs/experiments/README.md` and the agent knows them from `AGENTS.md`
- The prompt that starts every experiment, roughly: "Create `app/experiments/w1/<name>` with a full-screen canvas that ..." Then look at localhost:3000/experiments/w1/name and talk to it
- A variant is a new folder (`mouse-trail-2`), not an edit. Finished experiments stay as a record
- After each experiment that works: `git add .` → `git commit -m "w1: <name>"`. Before a risky change: commit. When the agent breaks it: `git restore .`
- If you fall behind, don't catch up on the code. Catch up on the loop: ask the agent to build what you saw, in your words

## 9. GLSL

<ImageRow
  items={[
    { src: "/lecture-materials/w1/glsl-face-voronoi.jpg", alt: "Face Voronoi, a GLSL experiment", caption: "One fragment shader: a Voronoi field in hue, every pixel computed on the GPU" },

/>

- What is <Term id="glsl" />?
  - OpenGL Shading Language: a small C-like language that runs on the GPU, not in Javascript
  - Your program runs once per vertex (vertex shader) and once per pixel (fragment shader), all of them in parallel
  - Fragment shader: given a pixel coordinate (and time, mouse, …), return a colour. That's it
  - Thousands of pixels at once → things that are too slow in a Canvas loop become free
- How does it connect to Three.js?
  - <Term id="shaderMaterial" />: a material whose vertex/fragment shaders you write yourself
  - <Term id="uniforms" />: values you pass from Javascript into the shader every frame (time, mouse, resolution, …)
  - A single full-screen plane + a fragment shader = a 2D canvas painted by the GPU
- What is it good for?
  - Per-pixel fields: gradients, noise, flow, distance fields, blur, feedback
  - Large numbers of particles / instances
  - Post-processing: effects over the whole frame
- Not good for: layout, text, UI logic. Let React/CSS do that
- References
  - The Book of Shaders [LINK](https://thebookofshaders.com/)
  - Shadertoy [LINK](https://www.shadertoy.com/)
  - Three.js ShaderMaterial [LINK](https://threejs.org/docs/#api/en/materials/ShaderMaterial)
