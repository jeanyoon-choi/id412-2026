## 5. 새 Next.js 앱 만들기 [#5-create-a-new-nextjs-app]

오늘은 두 단계, 이 순서로. 먼저 맨땅에서 빈 앱, 그다음 내 템플릿. 그래야 빈 Next.js 앱이 뭔지, 템플릿이 그 위에 뭘 더했는지 안다.

**1단계. VS Code와 터미널 열기**

1. VS Code를 연다. File → Open Folder… → 프로젝트를 모아둘 폴더를 고른다(없으면 만든다). 예: `Documents/code`. 이 워크숍의 모든 프로젝트가 이 폴더 안에 산다
2. VS Code 안에서 터미널을 연다: 메뉴 **Terminal → New Terminal**, 또는 단축키 `` Ctrl+` `` (`1` 왼쪽 키). 아래에 패널이 열린다. 그게 명령줄이고, 이미 방금 연 폴더를 가리키고 있다
3. 거기 뭔가를 치고 Enter를 누르면 네 컴퓨터에서 실행된다. 아래 전부가 이 패널에서 일어난다

**2단계. 앱 만들기**

1. `pnpm create next-app@latest`를 치고 Enter
   - `pnpm create` → "프로젝트 생성기를 돌려라"; `next-app@latest` → "Next.js 것, 최신 버전으로". pnpm이 내려받아 실행한다
2. 질문 몇 개가 나온다. 화살표로 고르고 Enter로 확정

```
✔ What is your project named? … scratch
✔ Would you like to use TypeScript? … Yes
✔ Would you like to use ESLint? … Yes
✔ Would you like to use Tailwind CSS? … No
✔ Would you like your code inside a `src/` directory? … No
✔ Would you like to use App Router? (recommended) … Yes
✔ Would you like to use Turbopack? … Yes
✔ Would you like to customize the import alias (`@/*` by default)? … No
```

   - 이름: `scratch` (아무거나). TypeScript **Yes**. Tailwind **No** (우리는 CSS Modules). `src/` No. App Router **Yes**. Turbopack Yes. Alias No
3. `Success! Created scratch at …`가 찍힌다. 왼쪽 파일 패널에 `scratch/` 폴더가 생겼고, 패키지도 이미 설치돼 있다
4. 문서: [create-next-app](https://nextjs.org/docs/app/api-reference/cli/create-next-app)

**3단계. 켜기**

1. `cd scratch` → "change directory": 터미널이 이제 새 폴더 안을 가리킨다. (또는 File → Open Folder → scratch, 그리고 새 터미널)
2. `pnpm dev` → "package.json의 dev라는 스크립트를 실행해라". 그 스크립트가 `next dev`다. 개발 서버를 켜서, 페이지를 즉석에서 만들고, 파일을 저장할 때마다 브라우저를 새로고침한다. 이렇게 보인다:

```
▲ Next.js 16.4.0 (Turbopack)
- Local:         http://localhost:3000
- Network:       http://192.168.0.12:3000
✓ Ready in 241ms
```

   - `Local: http://localhost:3000`이 주소다. `localhost` = 이 컴퓨터, `3000` = 서버가 듣는 포트
   - 터미널은 이제 서버를 돌리느라 바쁘다. 그냥 둬라. `Ctrl+C`로 끈다. 다른 명령을 치려면 터미널 패널의 `+`로 두 번째 터미널을 연다
3. Chrome에서 http://localhost:3000을 연다. Next.js 환영 페이지가 뜬다

**Hello World~! (scratch)**

1. 저 페이지는 어디서 오나? 파일 패널에서 `scratch/app/page.tsx`를 연다. 그 파일이 *곧* localhost:3000이다
   - `app/page.tsx` → `/`에서 보이는 것
   - `app/layout.tsx` → 모든 페이지를 감싸는 틀 (html, body, 폰트). 거의 안 건드린다
   - `app/globals.css` → 사이트 전체 스타일
   - `package.json` → 패키지 목록과 `dev` / `build` 스크립트. `pnpm dev`가 이걸 읽는다
   - 그게 전부다
2. `app/page.tsx`의 내용을 전부 이걸로 바꾸고 저장한다 (`Cmd+S` / `Ctrl+S`):

```tsx
export default function Home() {
  return (
    <main style={{ padding: "4rem", fontFamily: "sans-serif" }}>
      <h1>Hello World~!</h1>
      <p>This is app/page.tsx. Change this text and save.</p>
    </main>
  );
}
```

   - 페이지는 HTML처럼 생긴 코드(JSX)를 돌려주는 함수다. `export default`는 "이게 페이지다"라는 뜻
   - 브라우저가 알아서 바뀐다. 새로고침도, 재시작도 없다

## 6. ID412 워크숍 템플릿 사용 [#6-use-the-id412-workshop-template]

이제 템플릿. 기본 뼈대(방금 만든 것과 같은 앱, 거기에 이 노트와 실험용 폴더)와 에이전트 세팅(`AGENTS.md`, `docs/`)을 내가 미리 해둔 레포다. 수업 중에는 이걸 따라간다.

내 컴퓨터에 가져오는 방법은 둘이다. **방법 A**는 손으로, 모든 단계를 한 번은 직접 보라고. **방법 B**는 같은 단계를 에이전트에게 맡기는 것. 오늘은 A로 하고, 앞으로는 B를 써도 된다.

**방법 A · 1단계. GitHub에 내 사본 만들기**

1. GitHub에 로그인한 채로 https://github.com/jeanyoon-choi/id412-2026 을 연다
2. 초록 버튼 **Use this template** → **Create a new repository**
3. Repository name: `id412-yourname`. Public이든 Private이든 상관없다. **Create repository**
4. 이제 `github.com/YOURNAME/id412-yourname`이 생겼다. 네 것이고, 내 것과 연결돼 있지 않다

**방법 A · 2단계. 내 컴퓨터로 클론하기**

1. VS Code에서 프로젝트 폴더(아까의 `Documents/code`, `scratch` 안이 아니라)에서 터미널을 연다. `pwd` (Mac) / `cd` (Windows)로 확인: 터미널이 지금 어디인지 찍어준다
2. 네 GitHub 페이지에서 초록 **Code** 버튼 → HTTPS URL 복사. 그리고:

```
git clone https://github.com/YOURNAME/id412-yourname.git
```

   - `git clone` → "이 레포를 히스토리까지 통째로, 레포 이름의 새 폴더에 내려받아라"
3. File → Open Folder… → `id412-yourname`. 새 터미널을 연다 (이제 레포 안을 가리킨다)
4. `pnpm install` → `package.json`을 읽고, 적힌 패키지를 전부 `node_modules/`에 내려받는다. 처음엔 1분쯤 걸린다. 클론 직후 한 번, 그리고 `package.json`이 바뀔 때만 다시 한다
5. `pnpm dev` → http://localhost:3000. 이 노트가 네 컴퓨터에서 뜬다
6. `git remote -v` → 네 GitHub URL이 찍힌다. 클론은 이미 네 레포에 연결돼 있다. 나중에 `git push`하면 거기로 간다

**방법 B · 에이전트에게 시키기**

1단계(GitHub 사본)는 여전히 네가 클릭한다. 2단계의 1~5는 Claude Code가 해도 된다. 프로젝트 폴더에서 터미널을 열고 `claude`를 치고, 이렇게 말한다:

> https://github.com/YOURNAME/id412-yourname.git 을 이 폴더에 클론하고, pnpm으로 의존성을 설치하고, 실행하는 명령을 알려줘.

같은 명령을 실행하면서 하나하나 보여준다. 명령 실행 허가를 물으면, 명령을 읽고, 승인해라.

**Hello World~! (템플릿)**

1. localhost:3000 → 이 노트의 인덱스. 아까와 같은 `app/page.tsx`, 내용만 다르다
2. http://localhost:3000/experiments/w1/time-interval → 첫 실험. 어디에 뭐가 가는지 보라고 레포에 미리 넣어뒀다
3. http://localhost:3000/anything-else → 404 페이지. 템플릿은 `app/not-found.tsx`에 자기 것이 있다
4. 각 디렉토리는 뭘 하나?
   1. `app/` → 라우트/페이지를 다루는 곳. 대부분의 일이 여기서 일어난다
      1. `app/lecture-materials/` → 이 노트. 건드리지 않는다
      2. `app/experiments/w1/`, `w2/`, `w3/` → 수업 중 코딩, 실험 하나당 폴더 하나. 여기가 네 자리다
      3. `app/final/` → 네 기말 프로젝트
      4. `app/api/` → 서버 사이드 API 호출 (W3)
   2. `hooks/` → React 커스텀 훅 (`hooks/shared/useSocket.ts`, W2)
   3. `public/` → 에셋 보관 (이미지, 비디오, 3D 모델)
   4. `docs/` → 너와 에이전트를 위한 가이드. `AGENTS.md` → 에이전트의 규칙
   5. `node_modules/` → pnpm이 내려받은 패키지 코드. 고치지도, 커밋하지도 않는다
5. 코드 구조
   1. 실험 폴더마다 `page.tsx`와 `*.module.css`
      1. `page.tsx`: 로직과 JSX 컴포넌트
      2. `*.module.css`: <Term id="cssModules" /> 스타일링
   2. state, effect, 이벤트, 브라우저 API를 쓰면 첫 줄에 `"use client"`
   3. 파일은 <Term id="typescript" />(`.tsx`)다
6. 기말은 두 가지 다 된다: 이 템플릿의 `app/final/` 안에서 키우거나, 맨땅에서 새 앱을 만들어(5절) 필요한 것만 옮겨오거나. 이제 둘 다 할 줄 안다

## 7. 수업에서 실습하는 방식 [#7-how-we-work-in-class]

- 코드를 따로 주지 않는다. Claude Code를 같이 켜고, 빈 폴더에서 실험 하나하나를 현장에서 새로 만든다. 너도 네 노트북에서 동시에 똑같이 한다
- 루프: 설명한다 → 에이전트가 만든다 → 본다 → 뭐가 틀렸는지 말한다 → 반복
- 실험 하나 = 폴더 하나: `app/experiments/w1/<kebab-name>/`. 하는 일을 따서 이름 짓는다 (`time-interval`, `mouse-trail`). `test1`은 안 된다
  - 안에 `page.tsx` (+ `page.module.css`). 헬퍼는 옆에. 에셋은 `public/experiments/w1/<kebab-name>/`
  - 에이전트가 폴더에 짧은 `README.md`를 쓴다: 뭔지, 입력, 파라미터, 실행법. 규칙은 `docs/experiments/README.md`에 있고 에이전트는 `AGENTS.md`로 그걸 안다
- 모든 실험을 시작하는 프롬프트는 대충 이렇다: "`app/experiments/w1/<name>`에 화면 꽉 채운 캔버스를 만들고 ...". 그다음 localhost:3000/experiments/w1/name을 보면서 대화한다
- 변형은 새 폴더다 (`mouse-trail-2`). 고치지 않는다. 끝난 실험은 기록으로 남긴다
- 실험이 돌아갈 때마다: `git add .` → `git commit -m "w1: <name>"`. 위험한 변경 전에: 커밋. 에이전트가 망가뜨리면: `git restore .`
- 뒤처지면 본 것을 네 말로 에이전트에게 만들게 해라

## 9. GLSL [#9-glsl]

<ImageRow
  items={[
    { src: "/lecture-materials/w1/glsl-face-voronoi.jpg", alt: "Face Voronoi, GLSL 실험", caption: "프래그먼트 셰이더 하나: 색상으로 그린 보로노이 필드, 모든 픽셀을 GPU가 계산" },
  ]}

- <Term id="glsl" />이란?
  - OpenGL Shading Language: GPU에서 도는 작은 C 계열 언어. Javascript가 아니다
  - 프로그램이 정점마다 한 번(버텍스 셰이더), 픽셀마다 한 번(프래그먼트 셰이더), 전부 병렬로 실행된다
  - 프래그먼트 셰이더: 픽셀 좌표(그리고 시간, 마우스, …)를 받아 색을 돌려준다. 그게 전부다
  - 수천 개 픽셀을 한 번에 → Canvas 루프에서 너무 느린 것들이 공짜가 된다
- Three.js와는 어떻게 연결되나?
  - <Term id="shaderMaterial" />: 버텍스/프래그먼트 셰이더를 직접 쓰는 머티리얼
  - <Term id="uniforms" />: 매 프레임 Javascript에서 셰이더로 넘기는 값 (시간, 마우스, 해상도, …)
  - 화면 꽉 채운 평면 하나 + 프래그먼트 셰이더 = GPU가 그리는 2D 캔버스
- 무엇에 좋은가?
  - 픽셀 단위 필드: 그라데이션, 노이즈, 흐름, 거리 필드, 블러, 피드백
  - 대량의 파티클 / 인스턴스
  - 후처리: 프레임 전체에 거는 효과
- 안 맞는 것: 레이아웃, 텍스트, UI 로직. 그건 React/CSS에 맡겨라
- 레퍼런스
  - The Book of Shaders [LINK](https://thebookofshaders.com/)
  - Shadertoy [LINK](https://www.shadertoy.com/)
  - Three.js ShaderMaterial [LINK](https://threejs.org/docs/#api/en/materials/ShaderMaterial)
