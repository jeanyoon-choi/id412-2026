**코딩 agent란**

- 챗봇은 답만 한다. 코딩 agent는 **직접 실행한다**. 파일을 읽고, 수정하고, 명령어를 실행하고, 에러를 읽고, 브라우저를 열어 보고, 될 때까지 다시 시도한다. 사람이 원하는 것을 설명하면 agent가 만들고, 사람은 그 결과를 검토한다
- agent = 모델 + 도구 + 루프. 모델이 다음에 할 일을 정하면 도구가 그 일을 실행하고(파일 읽기, 파일 수정, `pnpm dev` 실행, 스크린샷 찍기), 결과가 다시 모델에게 돌아간다. 이 과정을 반복한다. 모든 단계는 화면에 표시되고, 언제든 멈출 수 있다
- agent의 기억은 대화의 컨텍스트 윈도우가 전부다. 프로젝트에 대해 아는 내용은 이번 세션에서 읽은 것과 `AGENTS.md`(아래)뿐이다
- 권한: 명령어를 실행하거나 프로젝트 밖의 파일을 건드릴 때는 먼저 허락을 구한다. 어떤 명령어인지 읽어 보고, 문제가 없으면 승인한다. "Allow all"은 나중에 쓴다

**agent와 일하는 법**

- 원하는 것을 구체적으로 설명한다. "App Router"라고 밝히고, 어느 파일인지 알려 주고, 에러는 그대로 붙여 넣는다
- 결과를 믿기 전에 무엇이 바뀌었는지 `git diff`로 읽어 본다. 버리려면 `git restore .`, 남기려면 `git commit`
- 한 번에 한 가지만 시킨다. 작은 단계로 나누고, 단계마다 브라우저에서 확인한다
- 레포에 있는 `AGENTS.md`가 이 프로젝트의 규칙을 agent에게 알려 준다. 바로 다음 항목에서 다룬다

**<Term id="harness">하네스</Term> 엔지니어링**

- 모델은 누가 써도 똑같다. *내 프로젝트에서* agent가 일을 잘하게 만드는 것은 모델을 둘러싼 나머지 전부, 곧 **하네스**다
- 하네스를 이루는 것: agent가 가장 먼저 읽는 규칙(<Term id="agentsMd" />), 참고하도록 안내받는 가이드(`docs/`), 작업 후 남겨 두는 기록(실험마다 `README.md` 하나), 반드시 통과해야 하는 검사(`pnpm typecheck`, `pnpm build`, 브라우저에서 라우트 열어 보기), 저장해 두는 체크포인트(제대로 동작하면 `git commit`)
- 하네스가 없으면 agent는 추측으로 일한다. 엉뚱한 폴더에 작업하고, 시키지도 않은 Tailwind를 쓰고, 2023년식 Pages Router로 짜고, 페이지를 한 번도 열어 보지 않은 채 "됩니다"라고 한다. 하네스가 있으면 같은 일을 매번 같은 방식으로 한다
- 2026년 10월 기준 최신 흐름: `AGENTS.md`는 여러 회사의 도구가 공통으로 쓰는 표준이다 (Codex, Claude Code, Cursor, Gemini가 모두 이 파일을 읽는다. [agents.md](https://agents.md/)). Next.js도 이 파일에 자체 블록을 써넣는다. 여기에 hook(수정할 때마다 타입체크 실행), skill(재사용하는 작업 절차), MCP(브라우저 같은 도구)가 더해진다. 이제는 prompt보다 하네스가 결과를 더 크게 좌우한다
- 이 템플릿에는 하네스가 이미 들어 있다. `AGENTS.md`와 `docs/`를 한 번 읽어 둔다. agent는 세션마다 읽는다. agent가 같은 실수를 반복하면 prompt가 아니라 하네스를 고친다

**브라우저 도구: Claude in Chrome**

- agent는 코드를 작성하지만, 브라우저가 없으면 결과 페이지를 볼 수 없다. 확장 프로그램(설치 방법은 아래)을 쓰면 agent가 직접 Chrome을 열어 http://localhost:3000 에 접속하고, 스크린샷을 찍고, 콘솔 에러를 읽고, 클릭하고, 입력하고, 스크롤한다
- 그러면 작업 루프가 완성된다. 수정 → 라우트 열기 → 화면 확인 → 콘솔 읽기 → 수정 → 다시 확인. 브라우저가 없으면 agent는 "될 겁니다"라고만 한다. 브라우저가 있으면 직접 확인한다
- 이렇게 요청한다. "localhost:3000/experiments/w1/time-interval 열어서 콘솔에 에러가 있는지 확인하고, 뭐가 보이는지 알려줘". 수정한 뒤에는 "페이지 열어서 원이 마우스를 따라오는지 확인해줘"
- agent는 눈에 보이는 Chrome 창에서 움직이므로 클릭 하나하나를 지켜볼 수 있다. 로그인해 둔 사이트도 agent가 볼 수 있으니, 신경 쓰이면 수업용 Chrome 프로필을 따로 만들어 쓴다
- VS Code 채팅 패널에서는 `@browser`를 입력해 agent에게 브라우저를 넘겨준다. 터미널에서는 `/chrome`으로 연결 상태를 확인하고, 연결이 끊겼을 때 다시 연결한다
- 문서: [Claude Code with Chrome](https://code.claude.com/docs/en/chrome)

**설치: Claude in Chrome (수업에서 같이 한다)**

1. Chrome에 [Claude in Chrome](https://chromewebstore.google.com/detail/claude/fcoeoabgfenejglbffodgkkbkcdhcgfn) 확장 프로그램을 설치한다 (Brave, Edge, Arc에서도 된다). Claude Code와 같은 계정으로 로그인한다
2. Claude Code 터미널에 `/chrome`을 입력하고 **Enabled by default**를 켠다. 상태가 "Extension: Installed"로 나오면 된다
3. "localhost:3000 열고 뭐가 보이는지 알려줘"라고 입력한다. Chrome이 알아서 탭을 연다

## 5. 새 Next.js 앱 만들기 [#5-create-a-new-nextjs-app]

오늘은 두 단계를 차례로 진행한다. 먼저 아무것도 없는 상태에서 빈 앱을 만들고, 그다음 내가 만든 템플릿을 쓴다. 이렇게 하면 빈 Next.js 앱이 어떤 것인지, 템플릿이 거기에 무엇을 더했는지 알 수 있다.

**1단계. VS Code와 터미널 열기**

1. VS Code를 연다. File → Open Folder…에서 프로젝트를 모아 둘 폴더를 고른다(없으면 새로 만든다). 예: `Documents/code`. 이 워크숍의 프로젝트는 모두 이 폴더 안에 둔다
2. VS Code 안에서 터미널을 연다. 메뉴에서 **Terminal → New Terminal**을 고르거나 단축키 `` Ctrl+` ``(`1` 왼쪽에 있는 키)를 누른다. 아래쪽에 패널이 열린다. 이 패널이 커맨드 라인이고, 방금 연 폴더가 이미 현재 위치로 잡혀 있다
3. 여기에 입력하고 Enter를 누르면 그 내용이 내 컴퓨터에서 실행된다. 아래 내용은 모두 이 패널에서 진행한다

<ImageRow
  items={[
    { src: "/lecture-materials/w1/vscode-terminal-dropdown.png", alt: "VS Code Terminal 메뉴", caption: "Terminal → New Terminal (이미지: VS Code 문서, CC BY 4.0)", href: "https://code.visualstudio.com/docs/terminal/basics" },
    { src: "/lecture-materials/w1/vscode-integrated-terminal.png", alt: "VS Code 통합 터미널", caption: "아래쪽에 열린 터미널 패널", href: "https://code.visualstudio.com/docs/terminal/basics" },

**2단계. 앱 만들기**

1. `pnpm create next-app@latest`를 입력하고 Enter를 누른다
   - `pnpm create`는 "프로젝트 생성 도구를 실행하라"는 뜻이고, `next-app@latest`는 "Next.js용 생성 도구의 최신 버전"이라는 뜻이다. pnpm이 이 도구를 내려받아 실행한다
2. 질문이 몇 가지 나온다. 방향키로 고르고 Enter로 확정한다

```
✔ What is your project named? … scratch
✔ Would you like to use the recommended Next.js defaults? › Yes, use recommended defaults
```

   - 이름은 `scratch`로 한다(다른 이름도 된다). 그다음 **Yes, use recommended defaults**를 고르면 TypeScript, ESLint, App Router, Tailwind, AGENTS.md가 설정된다. 이것으로 끝이다
3. `Success! Created scratch at …`가 출력된다. 왼쪽 파일 패널에 `scratch/` 폴더가 새로 생겼고, 패키지도 이미 설치되어 있다
4. 문서: [create-next-app](https://nextjs.org/docs/app/api-reference/cli/create-next-app)

**3단계. 실행하기**

1. 새로 생긴 폴더를 새 창에서 연다. **File → New Window**를 누르고, 새 창에서 **File → Open Folder… → `scratch`**를 고른 다음 **Terminal → New Terminal**을 연다. 창 하나에 프로젝트 하나, 그 프로젝트 폴더에서 시작하는 터미널 하나를 둔다. 항상 이렇게 하고, 터미널 하나에서 `cd`로 폴더를 옮겨 다니지 않는다
2. `pnpm dev`는 "package.json에 있는 dev라는 스크립트를 실행하라"는 뜻이다. 이 스크립트의 내용은 `next dev`이고, 개발 서버를 켠다. 개발 서버는 페이지를 그때그때 빌드하고, 파일을 저장할 때마다 브라우저를 새로고침한다. 터미널에는 이렇게 나온다.

```
▲ Next.js 16.4.0 (Turbopack)
- Local:         http://localhost:3000
- Network:       http://192.168.0.12:3000
✓ Ready in 241ms
```

   - `Local: http://localhost:3000`이 접속 주소다. `localhost`는 이 컴퓨터, `3000`은 서버가 열어 둔 포트다

## 6. ID412 워크숍 템플릿 사용하기 [#6-use-the-id412-workshop-template]

이제 템플릿을 쓴다. 기본 뼈대(방금 만든 것과 같은 앱에 이 강의 노트와 실험용 폴더를 더한 것)와 agent 설정(`AGENTS.md`, `docs/`)을 미리 갖춰 둔 레포를 만들어 두었다. 수업은 이 템플릿을 따라 진행한다.

템플릿을 내 컴퓨터로 가져오는 방법은 두 가지다. **방법 A**는 직접 손으로 하는 방법으로, 모든 단계를 한 번씩 눈으로 확인할 수 있다. **방법 B**는 같은 단계를 agent에게 맡기는 방법이다. 오늘은 A로 하고, 다음부터는 원하면 B를 써도 된다.

**방법 A · 1단계. GitHub에 내 복사본 만들기**

1. GitHub에 로그인한 상태에서 https://github.com/jeanyoon-choi/id412-2026 을 연다
2. 초록색 **Use this template** 버튼 → **Create a new repository**
3. Repository name에 `id412-yourname`을 입력한다. Public, Private 어느 쪽이든 괜찮다. **Create repository**를 누른다
4. 이제 `github.com/YOURNAME/id412-yourname`이 생겼다. 본인 소유의 레포이고, 내 레포와는 연결되어 있지 않다

**방법 A · 2단계. 내 컴퓨터로 클론하기**

1. **File → New Window**로 새 창을 열고 **File → Open Folder… → `Documents/code`**를 연다 (`scratch`가 아니라 프로젝트를 모아 두는 폴더다). **Terminal → New Terminal**을 연다
2. 본인 GitHub 레포 페이지에서 초록색 **Code** 버튼을 눌러 HTTPS URL을 복사한다. 그다음 터미널에 입력한다.

```
git clone https://github.com/YOURNAME/id412-yourname.git
```

   - `git clone`은 "이 레포를 히스토리까지 포함해, 레포와 같은 이름의 새 폴더에 내려받으라"는 뜻이다
3. 다시 **File → New Window**로 새 창을 열고 **File → Open Folder… → `id412-yourname`**을 연다. **Terminal → New Terminal**을 연다. 앞으로는 이 창에서 작업한다
4. `pnpm install` → `package.json`을 읽고, 거기 적힌 패키지를 모두 `node_modules/`에 내려받는다. 처음에는 1분 정도 걸린다. 클론한 직후에 한 번 실행하고, 그 뒤로는 `package.json`이 바뀌었을 때만 다시 실행한다
5. `pnpm dev` → http://localhost:3000. 이 강의 노트가 내 컴퓨터에서 열린다
6. `git remote -v` → 본인 GitHub URL이 출력된다. 클론한 폴더는 이미 본인 레포와 연결되어 있어서, 나중에 `git push`를 하면 그 레포로 올라간다

**방법 B · agent에게 맡기기**

1단계(GitHub에 복사본 만들기)는 이 방법에서도 직접 클릭해야 한다. 2단계의 2~5번은 Claude Code에게 맡길 수 있다. 프로젝트를 모아 두는 폴더를 연 창의 터미널에 `claude`를 입력하고 이렇게 요청한다.

> https://github.com/YOURNAME/id412-yourname.git 을 이 폴더에 클론하고, pnpm으로 의존성을 설치한 다음, 실행하는 명령어를 알려줘.

agent는 같은 명령어를 실행하면서 하나씩 보여 준다. 명령어를 실행해도 되는지 물으면, 명령어를 읽어 본 뒤 승인한다.

**Hello World~! (템플릿)**

1. localhost:3000 → 이 강의 노트의 목차. 앞에서 본 것과 같은 `app/page.tsx`이고 내용만 다르다
2. http://localhost:3000/experiments/w1/time-interval → 첫 번째 실험. 무엇이 어디에 들어가는지 볼 수 있도록 레포에 미리 넣어 두었다
3. http://localhost:3000/anything-else → 404 페이지. 템플릿에는 `app/not-found.tsx`에 따로 만든 404 페이지가 있다
4. 디렉토리별 역할
   1. `app/` → 라우트/페이지를 다루는 곳. 작업 대부분이 여기서 이루어진다
      1. `app/lecture-materials/` → 이 강의 노트. 수정하지 않는다
      2. `app/experiments/w1/`, `w2/`, `w3/` → 수업 중에 하는 코딩. 실험 하나에 폴더 하나. 여기가 본인 작업 공간이다
      3. `app/final/` → 기말 프로젝트
      4. `app/api/` → 서버에서 API를 호출하는 코드 (W3)
   2. `hooks/` → React custom hook (`hooks/shared/useSocket.ts`, W2)
   3. `public/` → 에셋(이미지, 영상, 3D 모델)을 두는 곳
   4. `docs/` → 사람과 agent가 함께 보는 가이드. `AGENTS.md` → agent가 따르는 규칙
   5. `node_modules/` → pnpm이 내려받은 패키지 코드. 수정하지 않고, 커밋하지도 않는다
5. 코드 구조
   1. 실험 폴더마다 `page.tsx`와 `*.module.css`가 있다
      1. `page.tsx`: 로직과 JSX component
      2. `*.module.css`: <Term id="cssModules" />로 작성한 스타일
   2. state, effect, 이벤트, 브라우저 API를 쓸 때는 첫 줄에 `"use client"`를 적는다
   3. 파일은 <Term id="typescript" />(`.tsx`)로 작성한다
6. 기말 프로젝트는 두 가지 방식 중 어느 쪽으로 해도 된다. 이 템플릿의 `app/final/` 안에서 작업을 키워 가도 되고, 5절처럼 새 앱을 처음부터 만든 뒤 필요한 것만 옮겨 와도 된다. 이제 두 방법 모두 할 수 있다

## 7. 수업 진행 방식 [#7-how-we-work-in-class]

- 코드는 나눠 주지 않는다. Claude Code를 함께 열고, 빈 폴더에서 시작해 실험을 하나씩 그 자리에서 만든다. 학생도 각자 노트북에서 동시에 똑같이 따라 한다
- 작업 루프: 원하는 것을 설명한다 → agent가 만든다 → 결과를 본다 → 잘못된 부분을 말한다 → 반복한다
- 실험 하나에 폴더 하나를 쓴다: `app/experiments/w1/<kebab-name>/`. 폴더 이름은 `test1`처럼 짓지 않고, 실험이 하는 일을 따서 짓는다 (`time-interval`, `mouse-trail`)
  - 폴더 안에 `page.tsx` (+ `page.module.css`)를 둔다. 헬퍼 파일은 그 옆에 둔다. 에셋은 `public/experiments/w1/<kebab-name>/`에 둔다
  - agent가 폴더 안에 짧은 `README.md`를 쓴다. 어떤 실험인지, 입력, 파라미터, 실행 방법을 적는다. 작성 규칙은 `docs/experiments/README.md`에 있고, agent는 `AGENTS.md`를 통해 이 규칙을 안다
- 실험을 시작할 때 쓰는 prompt는 대체로 이런 식이다. "`app/experiments/w1/<name>`에 화면을 가득 채우는 canvas를 만들고 ..." 그다음 localhost:3000/experiments/w1/name 을 보면서 agent와 대화를 이어 간다
- 변형을 만들 때는 기존 폴더를 고치지 않고 새 폴더를 만든다 (`mouse-trail-2`). 끝난 실험은 기록으로 남겨 둔다
- 실험이 제대로 동작할 때마다 `git add .` → `git commit -m "w1: <name>"`. 위험한 변경을 하기 전에는 커밋한다. agent가 코드를 망가뜨리면 `git restore .`
- 진도를 놓쳤으면, 화면에서 본 것을 본인 말로 설명해서 agent에게 만들어 달라고 한다

- <Term id="canvas" />란?
  - 비트맵으로 된 HTML 요소다. Javascript로 그 위에 그린다. `getContext("2d")`를 호출한 다음 `fillRect`, `arc`, `lineTo`, `drawImage`를 쓴다
  - 그린 내용은 기억되지 않는다. 프레임마다 지우고 다시 그린다. 이 루프는 `requestAnimationFrame`으로 돌린다
  - Canvas vs <Term id="svg" />: SVG는 DOM 안에 있는 도형이다. 선명하고 스타일을 입힐 수 있으며, 요소 수백 개까지는 무리가 없다. Canvas는 픽셀이다. 수천 개를 매 프레임 그린다
- React에서는 `useRef`로 요소를 가져오고, `useEffect`에서 루프를 시작하고 cleanup에서 멈춘다. 크기는 `innerWidth/innerHeight` × `devicePixelRatio`로 잡는다
- 파라미터는 시간과 마우스로, 다음에 나올 GLSL과 같다. 다른 점은 Canvas는 CPU에서 도형을 하나씩 그리고, GLSL은 GPU에서 모든 픽셀을 한꺼번에 계산한다는 것이다

## 10. GLSL [#10-glsl]

<ImageRow
  items={[
    { src: "/lecture-materials/w1/glsl-face-voronoi.jpg", alt: "Face Voronoi, GLSL 실험", caption: "fragment shader 하나로 그린 보로노이 필드. 색상(hue)으로 표현했고, 모든 픽셀을 GPU에서 계산한다" },
  ]}
  wide
/>

- <Term id="glsl" />이란?
  - OpenGL Shading Language. C와 비슷한 작은 언어로, Javascript 안이 아니라 GPU에서 실행된다
  - 작성한 프로그램은 정점마다 한 번(vertex shader), 픽셀마다 한 번(fragment shader) 실행되고, 이 실행은 모두 병렬로 이루어진다
  - fragment shader는 픽셀 좌표(그리고 시간, 마우스, …)를 받아 색 하나를 반환한다. 하는 일은 이것뿐이다
  - 수천 개의 픽셀을 한꺼번에 처리한다 → Canvas 루프로는 너무 느린 작업도 부담 없이 돌아간다
- Three.js와는 어떻게 연결되나?
  - <Term id="shaderMaterial" />: vertex/fragment shader를 직접 작성해서 쓰는 머티리얼
  - <Term id="uniforms" />: Javascript에서 shader로 매 프레임 넘겨주는 값 (시간, 마우스, 해상도, …)
  - 화면을 가득 채운 평면 하나 + fragment shader = GPU가 그리는 2D canvas
- 어디에 쓰면 좋은가?
  - 픽셀 단위로 계산하는 필드: 그라데이션, 노이즈, 흐름, distance field, 블러, 피드백
  - 아주 많은 수의 파티클 / 인스턴스

- <Term id="threejs" />란?

  - Vanilla Three.js = Vanilla Javascript + Three.js

  - React-Three에 속하지는 않지만, <Term id="reactSpring">React Spring</Term> (애니메이션 라이브러리) [LINK](https://www.react-spring.dev/)
- 왜 Three.js인가?
  - Cinema 4D: 정적인 3D 영상, GUI 기반, 접근성 높음, 인터랙티브성 낮음
  - Unity: 인터랙티브 3D 게임, GUI + C# 코딩, 접근성 낮음, 인터랙티브성 높음
  - Three.js: 인터랙티브한 웹 기반 3D 환경, Javascript 코딩, 접근성 중간, 인터랙티브성 중간

    - 접근하기 쉬운 데모 (설치 불필요)

<ImageRow

1. 배포: localhost에서 만든 웹앱을 인터넷에 올려 전 세계 어디서나 접속할 수 있게 하는 일!
2. Next.js → <Term id="vercel" />로 쉽게 배포할 수 있다
3. Vercel에 가입한다 https://vercel.com/
4. 먼저 코드를 GitHub에 push해야 한다. VS Code 터미널에 다음을 입력한다
   1. `git add .`
   2. `git commit -m "Update"`
   3. `git push`
5. 이제 GitHub 레포의 코드가 최신 상태가 되었다
6. Vercel로 이동한다 https://vercel.com/
7. Add New > Project > Import Git Repository > 'Import' > **Framework Preset을 Next.js로 설정 >** Deploy
8. 짠!
9. 이제부터는 `git push`할 때마다 다시 배포된다
